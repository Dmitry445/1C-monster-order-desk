# Настройка Monster Order Desk

Минимальная настройка окружения для запуска проекта.

Требования: Node.js 20 и npm. Полный список возможностей находится в
[README.md](README.md), здесь описана только настройка окружения.

## Переменные окружения

1. Создайте локальный `.env` на основе `.env.example`.
2. Задайте обязательные `ODATA_BASE_URL`, `ODATA_USERNAME` и `ODATA_PASSWORD`.
3. При необходимости измените `PORT`, OData-таймауты, интервалы клиента и
   `CORS_ORIGINS`; значения по умолчанию и назначение переменных описаны в README.

Не добавляйте `.env` и реальные учётные данные в код, задачи VS Code, документацию или логи.

## Быстрый запуск

```bash
npm install
npm run dev
```

В development клиент доступен на `http://localhost:5173`, API — на
`http://localhost:3000`. Vite проксирует запросы `/api` на порт из `PORT`.

Для production:

```bash
npm run build
npm start
```

Собранное приложение доступно на `http://localhost:3000`, если `PORT` не переопределён.

Для сборки и запуска десктопной версии Electron:

```bash
npm run build:electron
npm run package:win
```

Команда `npm run build:electron` собирает клиент, сервер и файлы главного процесса Electron в `dist-electron`. Скрипт `package:win` создаёт автономный `.exe` (Portable) и установщик NSIS в каталоге `dist-electron-build`.

## Настройка установленной Windows-версии

Конечному пользователю не нужно устанавливать Node.js, npm или редактировать `.env`. После запуска desktop-версии откройте «Настройки», укажите URL OData, логин и пароль 1С и сохраните параметры. Приложение сначала проверит соединение, затем сохранит конфигурацию в `%APPDATA%\Monster Order Desk\config.json`. Настройки применяются после перезапуска приложения; при первом запуске без конфигурации окно настроек открывается автоматически.

`config.json` содержит URL, логин и пароль в открытом виде. Приложение не шифрует этот файл, поэтому
его защита зависит от ACL профиля Windows. Не копируйте файл в диагностику, общий каталог или архив
дистрибутива; при смене пользователя удалите его после закрытия приложения.

Минимальные требования к Windows-дистрибутиву: Windows 10 или новее, x64, доступ к сети организации и опубликованный endpoint 1С OData. Встроенный сервер работает только на loopback-интерфейсе `127.0.0.1`; внешний доступ к нему не требуется.

Инструкция для конечного пользователя также включается в пакет как `resources/README.txt`.

## Тестовые данные

Для проверки на текущем демо-стенде можно использовать заказ **00ДМ-000101**:

- Ref_Key: `2da145f0-d5fc-11f1-a0b3-48df371887e9`
- Клиент: Воронцов Пётр Аркадьевич
- 4 строки товаров с разными ставками НДС
- Склад: Центральный склад

Демо-данные принадлежат внешней 1С и могут измениться. Автоматические проверки используют те же
идентификаторы из `e2e/helpers.ts`; создание реализации изменяет демо-базу и должно выполняться
осознанно.

Для безопасной проверки формы остатков доступны три EAN-13. Они выполняют только чтение из 1С:

| EAN-13          | Номенклатура                  |
| :-------------- | :---------------------------- |
| `4600100000014` | Бумага офисная А4, 500 листов |
| `4600100000021` | Ручка шариковая синяя         |
| `4600100000038` | Папка-регистратор 75 мм       |

Нажмите нужную тестовую строку под единым полем поиска, затем «Проверить остаток». Форма сама
распознает корректный EAN-13 и не отправит его как номер заказа. Общий список хранится в
`src/shared/demoBarcodes.ts`; при изменении демо-базы его нужно обновить вместе с ожидаемыми
названиями.

## Ключевые решения

**Остатки на складе**: показываем значение `ВНаличииBalance` из регистра `AccumulationRegister_ТоварыНаСкладах/Balance` на момент запроса.

**Расчёты**: все операции в копейках с округлением половина вверх, НДС считается от округлённой суммы строки, итоги — сумма построчных значений.

**Склонение**: по правилам русской морфологии, пол определяется по отчеству.

**Обработка ошибок 1С**: до трёх попыток только для безопасных GET-запросов; POST создания реализации не повторяется.

Команды разработки и проверки приведены в [DEVELOPMENT.md](DEVELOPMENT.md), архитектурные границы —
в [ARCHITECTURE.md](ARCHITECTURE.md).
